# Architecture decision records

One file per architectural decision: the context it was taken in, what was
decided, and what that costs. Code shows what was built and `git log` shows
when; these exist to keep why, especially why the alternatives were turned down.

A record is not edited once accepted. A decision that changes gets a new record
that says which one it supersedes, so the reasoning stays readable in order.

| Status | Meaning |
| --- | --- |
| Proposed | Written down, not yet agreed |
| Accepted | In force |
| Superseded by N | Replaced; kept for the trail |
