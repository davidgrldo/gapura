Gapura {{ .Chart.AppVersion }} installed as {{ include "gapura.fullname" . }} in namespace {{ .Release.Namespace }}.

1. Wait for the controller to become ready:
     kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "gapura.fullname" . }}

2. Point a Gateway at this class:
     apiVersion: gateway.networking.k8s.io/v1
     kind: Gateway
     metadata: { name: main }
     spec:
       gatewayClassName: {{ (.Values.gatewayClass).name }}
       listeners:
       - { name: http, port: {{ (.Values.ports).http }}, protocol: HTTP }

3. Read its status:
     kubectl get gateway main -o jsonpath='{.status.conditions[?(@.type=="Programmed")].status}{"\n"}'

4. A NodePort install publishes an address that carries no port, so a request has to add the
   NodePort to it by hand — the address in Gateway status is never enough on this install:
{{- if ((.Values.service).nodePorts).http }}
     curl -H 'Host: echo.example' "http://{{ $addr }}:{{ ((.Values.service).nodePorts).http }}/echo?msg=it-works"
{{- else }}
     NODEPORT=$(kubectl -n {{ .Release.Namespace }} get svc {{ include "gapura.fullname" . }} -o jsonpath='{.spec.ports[?(@.name=="http")].nodePort}')
     curl -H 'Host: echo.example' "http://{{ $addr }}:${NODEPORT}/echo?msg=it-works"
{{- end }}
{{- if not .Values.publishAddresses }}
   NODE_IP is any node's address, e.g.: kubectl get nodes -o wide
{{- end }}
{{- end }}

Metrics, health and the routing table live on the admin port ({{ (.Values.ports).admin }}) of the
ClusterIP Service {{ include "gapura.fullname" . }}-admin. They are deliberately kept off the
public Service:
     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "gapura.fullname" . }}-admin {{ (.Values.ports).admin }}:{{ (.Values.ports).admin }}
     curl -s localhost:{{ (.Values.ports).admin }}/debug/config | head -20

The console is enabled and served by {{ include "gapura.fullname" . }}-control on port
{{ ((.Values.console).service).port }} -- sign-in requires the OIDC provider named in
console.oidc.issuer and the two Secrets it points at.
{{- if not (((.Values.console).oidc).scopes) }}
   Check console.oidc.scopes before the first sign-in: a provider only puts a claim in the
   ID token when the scope carrying it was asked for, and an absent claim is indistinguishable
   from a reader granted nothing -- every sign-in would see an empty console with no error.
   (dex: the email claim needs the email scope; keycloak realms may require their groups scope.)
{{- end }}
{{- end }}

The GatewayClass {{ (.Values.gatewayClass).name }} is cluster-scoped. A second release of this chart
in the same cluster needs its own gatewayClass.name and controllerName.

The Gateway API CRDs are not part of this chart. Install the standard channel yourself:
     kubectl apply -f https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.6.2/standard-install.yaml
This build is made for the v1.6.2 standard channel. On an older one the API server serves no
backendtlspolicies, the controller logs the absent kind and disables TLS to backends, and
upgrading the CRDs to that channel is picked up within a minute, no restart.
